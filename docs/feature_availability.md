# Forecast feature availability matrix

Use this table when choosing model inputs. Decision time is an exact UTC hour `t`. A feature must be computable using records **available by t**, not merely records whose event timestamp precedes t. Local historical files generally lack ingestion times and release-vintage histories. No feature matrix or model is built here.

| Candidate / source fields | Before prediction? | Proposed disposition and required handling |
| --- | --- | --- |
| UTC hour, day of week, month, season, calendar year | Known from t | Eligible. Derive from the decision timestamp only; cyclic encoding is a teammate implementation choice. |
| County/state IDs from the fixed 534-county study roster | Known for the requested location | Eligible grouping keys and candidate categorical predictors. Fit encoders on training data; report performance by county and state. County names add no independent information. |
| Latest observed `customers_out` at/before t | Timestamp available; arrival time unverified | Conditional retrospective feature. Require `available_at <= t` when available. Otherwise name the assumed reporting lag explicitly; do not claim operational availability. Never use a future reading to fill a gap. |
| Lagged outage values, trailing 1/6/12/24-hour max/median/trend | Conditional on source arrival | Use only trailing records timestamped at/before `t - assumed_lag`. Preserve missingness; changes require two observed values and elapsed time. Do not treat missing as zero. Exclude duplicate/invalid readings under a documented past-only rule. |
| Trailing observation count, time since last reading, missing flags | Conditional on source arrival | Candidate past-coverage features. Derive only from the lookback period. Do not use future window completeness, a later year's coverage, or a full-data county retention rate. |
| Same-year ACS `population`, `housing_units`, derived densities | No release evidence in stored year labels | Exclude from the primary forecast feature set until release dates/vintages are documented. An estimate labeled year y is not proof it existed during year y. A one-year lag is not automatically sufficient. |
| `land_sqmi`, `pop_density`, `housing_density` | Stored area comes from a later reference vintage; densities also depend on ACS | Retrospective descriptive fields for now. Freeze a documented geography/reference vintage before admitting them as forecast features. Do not use same-year density as a shortcut around ACS availability. |
| MCC customer estimates | No as-of history established | Diagnostic denominator only. Not needed for the absolute-customer target. Exclude from primary forecast features pending provenance and release timing. |
| Annual coverage-history and DQI values | Annual retrospective summaries | Quality diagnostics, not same-year predictors. Past-year versions require verified release dates; they cannot substitute for county-level coverage. |
| NOAA `event_type`, `magnitude`, `magnitude_type`, tornado scale/length/width, flood cause, category | Historical event attributes; no pre-event release evidence | Exclude from primary forecast predictors. Useful only for retrospective EDA/subgroup attribution. An event start time before t does not prove the completed report existed by t. |
| NOAA event start/end, duration, reported location, coordinates, episode/event IDs, source | Final historical report fields | Exclude as forecast predictors and cohort filters. In particular, future event duration and end time leak future information. IDs are joining/audit keys, not explanatory measurements. |
| NOAA damages, injuries, deaths, narratives, derived text features | Post-event outcomes/descriptions | Exclude. Text can explicitly describe outages and impacts; embedding it does not remove leakage. |
| Zone-to-county lookup, mapping corrections | Static local lookup lacks full historical vintages | Retrospective join support only. The overlay corrects documented code/name conflicts; it does not establish historical zone boundaries or prediction-time weather availability. |
| Future peak, >threshold label, future coverage, anomaly flags, proxy exclusion status | After t | Targets or outcome-audit fields only. Never predictor inputs. Future eligibility cannot determine where forecasts are issued. |
| Notebook 03 peak share, burden, time-to-peak, capped hourly outcome, storm-window joins | Use event/outcome windows | Descriptive EDA only. They are not the approved forecast targets and cannot become advance predictors. |
| Weather forecasts, warnings, utility operations, infrastructure | Not present as issue-time data in this repo | Unavailable under current scope. Do not simulate availability from later storm reports or invent these inputs. |

## As-of construction contract

Keep `fips_code`, `decision_time`, horizon and split as audit keys. For each derived feature, record its source, lookback, aggregation, assumed or observed latency, null policy and latest permitted source timestamp. Past-only aggregates may cross a split's start because past observations would have been known at prediction time; fitted scalers, imputers, encoders and learned transformations cannot be fit on validation/test records.

For an initial historical baseline, compare explicitly declared lag assumptions (for example 0, 1 and 3 hours) only within development/validation data. These are scenarios, not measured delivery delays or approved operational settings. The forecast cannot be called deployable until latency is measured and as-of availability is established. Missing lagged values should remain missing with indicators or use training-fitted imputation; no interpolation using later observations.

Keep a calendar/geography-only reference and, conditionally, an outage-history reference. These are comparison specifications for the teammate, not algorithms selected or trained in this EDA. An all-negative classifier is a useful diagnostic: it has high accuracy under class imbalance but zero severe-outage recall.
